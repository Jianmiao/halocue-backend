# HaloCue 制作能力适配器契约 v1

状态：面向未来 0.9.2 稳定能力的防腐层设计。当前不接入、不导入、不修改 `01-完整程序/aa/` 或其 worktree。

## 1. 目的

正式版作品、版本与任务模型只能依赖此契约，不能依赖当前 `director_state`、`director_policy`、Prompt、Agent、全局 `JOB`、WebUI DOM 或临时文件布局。

适配器负责把稳定的正式版输入翻译为某个制作引擎版本可以执行的请求，再把结果和错误归一化。它不拥有作品正文，不决定 ScriptRelease，也不静默修改输入。

## 2. 能力发现

```json
{
  "adapter_api_version": "1.0",
  "engine_id": "halocue-production",
  "engine_version": "unbound",
  "capabilities": [
    "preflight",
    "performance_draft",
    "validate_build",
    "compile_aap"
  ],
  "supported_script_manifest_versions": ["1.0"],
  "supported_asset_manifest_versions": ["1.0"]
}
```

UI 必须先读取能力，再决定显示哪些动作。缺少能力时显示明确不可用状态，不能假装执行成功。

## 3. 固定输入

每次制作运行创建不可变的 `ProductionRequest`：

```json
{
  "request_id": "uuid",
  "script_release": {
    "id": "uuid",
    "display_version": "v4",
    "content_hash": "sha256:...",
    "manifest_uri": "workspace://releases/v4/manifest.json"
  },
  "script_manifest_version": "1.0",
  "asset_manifest": {
    "version": "1.0",
    "content_hash": "sha256:...",
    "uri": "workspace://assets/manifest.json"
  },
  "production_policy": {
    "asset_reference_mode": "whitelist_only",
    "allow_placeholders": false,
    "target": "pc_aap"
  },
  "idempotency_key": "sha256:request-content"
}
```

约束：

- URI 由正式版工作区解析器提供，适配器不得接受任意系统路径穿越工作区。
- 所有素材引用必须出现在固定哈希的白名单 manifest 中。
- 请求不包含聊天记录、API Key、未采纳 Proposal、可变草稿或模型配置 UI 状态。
- 相同 `idempotency_key` 不代表复用中断进程；它用于识别相同业务输入和避免重复发布结果。

## 4. 操作

### `preflight(request)`

检查剧本结构、角色/素材映射需求和制作可行性，不生成 `.aap`。

输出：

```json
{
  "report_ref": "artifact://preflight/uuid",
  "status": "passed_with_warnings",
  "work_items": [],
  "blockers": [],
  "warnings": []
}
```

### `create_performance_draft(request, scope)`

为全部或指定 Scene 生成可审查演出草稿。模型只能产出人可读的演出候选，不能直接写 `.aap`。

`scope` 必须是稳定 Scene ID 集合；空集合表示全 Release。输出必须标明每段候选对应的 Scene ID、输入哈希和证据。

### `validate_build(request, performance_draft_ref)`

执行格式、素材引用闭合、目标兼容和确定性编译前检查。输出结构化 Gate 结果，不用自由文本代替错误码。

### `compile_aap(request, approved_performance_draft_ref)`

只接受已审查并固定哈希的 PerformanceDraft。输出不可变 BuildBundle：

```json
{
  "build_bundle_ref": "artifact://build/uuid",
  "input_hashes": {
    "script_release": "sha256:...",
    "performance_draft": "sha256:...",
    "asset_manifest": "sha256:..."
  },
  "compiler": {"id": "...", "version": "..."},
  "aap_ref": "workspace://builds/uuid/output.aap",
  "aap_hash": "sha256:...",
  "warnings": []
}
```

安装和 Android 公共目录导出不是 `compile_aap` 的隐式副作用，必须是上层单独、明确的用户操作。

## 5. 事件与进度

适配器可发送进度事件，但数据库状态由正式版运行服务拥有：

```text
operation_started
stage_progress
artifact_created
waiting_user
operation_succeeded
operation_failed
```

每个事件包含 `request_id`、`work_item_id`、`attempt_id`、单调递增 `sequence` 和时间戳。进度百分比只用于展示，不作为成功依据；成功必须有经校验的输出 Artifact。

## 6. 错误模型

```json
{
  "code": "ASSET_REFERENCE_NOT_ALLOWED",
  "category": "validation",
  "message": "面向用户的简短说明",
  "detail_ref": "artifact://errors/uuid",
  "retryability": "after_user_action",
  "scope_refs": ["scene:uuid"],
  "caused_by_attempt": "uuid"
}
```

标准类别：

| category | 示例 | retryability |
|---|---|---|
| `invalid_input` | 清单版本不支持、哈希不一致 | `never` 或修正后新建 WorkItem |
| `validation` | 素材越权、脚本结构不闭合 | `after_user_action` |
| `model_transient` | 限流、网络中断 | `automatic` |
| `model_output` | 输出无法解析、违反候选格式 | 按策略有限重试 |
| `compiler` | 确定性编译失败 | 修正输入后重试 |
| `environment` | 磁盘不足、依赖缺失 | `after_user_action` |
| `cancelled` | 用户取消 | `never`，需要新 Attempt |

不得通过字符串包含关系判断错误类别。

## 7. 恢复、重试与取消

- ProductionRun 与 WorkItem 由正式版持久化并恢复。
- 每次外部模型调用或编译启动都创建新 JobAttempt。
- 应用退出或引擎进程消失后，旧 Attempt 标记为 `abandoned`。
- 可重试错误通过新 Attempt 执行；旧日志和部分输出保留用于审计，但不得冒充完成产物。
- 取消是尽力终止当前执行，并可靠阻止结果被提交；如果执行晚到返回，按已取消 Attempt 丢弃，不写入当前 Artifact 指针。
- Artifact 提交采用“写临时文件 -> 校验 -> 计算哈希 -> 原子移动 -> 数据库事务登记”。

## 8. 局部重跑与版本升级

制作发现正文问题时返回 `source_scene_id` 和证据，不直接修改剧本。创作侧产生新 ScriptRelease 后，由正式版执行影响分析：

```json
{
  "from_release": "v3",
  "to_release": "v4",
  "changed_scenes": ["scene:uuid"],
  "invalidated_artifacts": ["performance_segment:uuid"],
  "reusable_artifacts": ["performance_segment:uuid"],
  "required_work_items": []
}
```

只有用户确认“升级制作引用版本”后才新建或更新 Run 的后继链路。原 Run 和原 BuildBundle 保留可审计。

## 9. 安全与发布边界

- 适配器日志必须脱敏，不记录 API Key、完整模型请求正文和本机绝对路径。
- 禁止引用素材白名单外的文件。
- 禁止修改、重签、注入原版 AA。
- PC 的安装动作和 Android 的公共导出动作必须分别陈述能力；Android 公共导出不等于写入原 AA 的 `Android/data`。
- 开源依赖进入实现前逐项记录许可证、版本、使用方式和是否分发；只借鉴 GPL/AGPL 项目的交互或架构时不得复制其代码。

## 10. 适配器验收测试

1. 同一固定输入执行两次，生成内容等价且可验证哈希的 BuildBundle。
2. 中断模型请求后重启应用，创建新 Attempt 而不重复创建 ScriptRelease。
3. 制作期间创作侧发布 vNext，当前 Run 输入不改变。
4. 越过素材白名单的引用被结构化错误阻止。
5. 取消后晚到结果不能成为正式 Artifact。
6. 单场剧本变化只使对应演出段失效，未影响段可复用。
7. 适配器不存在时，作品与创作工作台仍可完整工作。
8. 错误详情不泄露密钥、本机路径、私有草稿或完整模型请求。
