# HaloCue 正式版领域模型 v1

状态：设计契约，不是 0.9.2 实现。本文中的表名、字段名和状态机用于正式版原型评审；在正式接入前不得反向要求 0.9.2 修改内部模型。

## 1. 聚合边界

正式版分成四个边界：

1. **作品域**：作品结构、正文、创作基准与发布版本。
2. **候选与审查域**：Agent 提案、Diff、证据、Gate 与人工决定。
3. **运行域**：长期可恢复的 ProductionRun、WorkItem 与短暂 JobAttempt。
4. **制作域**：固定引用 ScriptRelease，产生 PerformanceDraft、BuildBundle 与 `.aap`。

聊天、Prompt、模型响应和当前进程状态都不是聚合根，也不是事实源。

## 2. 标识与通用规则

- 所有持久对象使用不随重命名变化的 UUID。
- 人可读编号仅用于展示，例如 `ScriptRelease v4`、`ProductionRun #14`。
- 所有 Revision 和 Release 记录 `content_hash`、`created_at`、`created_by` 与来源版本。
- 正文、JSON 与 Markdown 产物使用原子替换；SQLite 保存关系、状态、索引和审计记录。
- 不可变对象禁止 UPDATE 内容，只能创建后继版本。
- 删除默认是归档；被 Release、Run 或审计记录引用的对象不可物理删除。

## 3. 作品域

### Work

一部长期作品，是创作域聚合根。

```text
Work
  id
  title
  status: active | archived
  active_writing_pack_version
  current_canon_revision_id
  created_at / updated_at
```

### Chapter 与 Scene

```text
Chapter
  id / work_id
  stable_order_key
  title
  status: planned | drafting | review | released

Scene
  id / chapter_id
  stable_order_key
  title
  status: planned | drafting | review | released
  current_revision_id
  current_scene_contract_revision_id
```

移动或改名不改变 `id`。发布版本引用 Scene 身份和特定 Revision，而不是依赖标题或数组下标。

### Artifact 与 Revision

Artifact 是可版本化产物的稳定身份，Revision 是一次不可变内容快照。

```text
Artifact
  id / work_id
  kind: brief | story_blueprint | work_canon | volume_outline |
        chapter_outline | scene_contract | character_card |
        scene_script | script_candidate | performance_draft | build_bundle
  scope_type / scope_id

Revision
  id / artifact_id
  parent_revision_id?
  schema_version
  content_uri
  content_hash
  provenance_json
  created_by: user | agent | importer | system
  created_at
```

`provenance_json` 至少记录输入 Revision、WritingPack 版本、模型与参数摘要、Proposal 和 JobAttempt。不得记录 API Key。

### ScriptRelease

供制作固定引用的不可变剧本清单。

```text
ScriptRelease
  id / work_id / display_version
  manifest_uri / content_hash
  canon_revision_id
  writing_pack_version
  source_revision_ids[]
  gate_snapshot_ids[]
  released_by / released_at
```

约束：

- Release 创建后内容、清单和 Canon 引用不可修改。
- 新正文只能形成 ScriptRevision，再冻结为新 ScriptRelease。
- 制作升级版本必须新建影响分析和 WorkItem，不能静默切换引用。
- 导入已有剧本可创建 `Imported ScriptRelease`，但仍须保存解析结果、来源文件哈希和人工确认。

## 4. 候选与审查域

### Proposal

```text
Proposal
  id / work_id
  scope_type / scope_id
  base_revision_id
  proposed_revision_payload_uri
  diff_uri
  evidence_refs[]
  risk: low | medium | high
  status: pending | accepted | rejected | superseded
  created_by / created_at
  decided_by? / decided_at?
```

采纳 Proposal 的事务顺序：校验 base Revision 仍是当前版本，创建新 Revision，记录决定，再更新可变指针。若 base 已过期，Proposal 进入 `superseded`，必须重新生成 Diff。

### Gate 与 Blocker

```text
Gate
  id / run_id?
  kind
  scope_ref
  status: pending | running | passed | warning | blocked
  result_snapshot_uri

Blocker
  id / gate_id? / work_item_id?
  code
  severity: warning | blocking
  evidence_refs[]
  resolution_status: open | resolved | waived
  resolution_note / resolved_by / resolved_at
```

`waived` 必须是显式人工决定，且保留原因。ScriptRelease 不允许存在未解决的创作阻塞项；BuildBundle 不允许存在未解决的编译、素材白名单或格式阻塞项。

## 5. 运行域

### ProductionRun

一次从固定输入推进到交付物的长期运行。

```text
ProductionRun
  id / work_id
  kind: creation | production
  automation_level: guided | milestone | fast
  pinned_input_refs[]
  status: planned | running | waiting_user | blocked | completed | cancelled
  created_at / updated_at
```

ProductionRun 只引用固定输入。创作 Run 可以产生新 Revision；制作 Run 必须固定引用一个 ScriptRelease。

### WorkItem

```text
WorkItem
  id / run_id
  type / scope_ref
  dependency_ids[]
  input_refs[] / output_refs[]
  acceptance_criteria_json
  status: queued | ready | running | waiting_user | blocked | succeeded | cancelled
  attempt_count
  lease_owner? / lease_expires_at?
```

WorkItem 是可恢复的业务步骤。应用崩溃后根据持久状态继续调度，不根据内存中的 Promise 或线程猜测结果。

### JobAttempt

```text
JobAttempt
  id / work_item_id / ordinal
  provider / model_or_engine
  request_digest
  status: started | succeeded | failed | abandoned
  started_at / finished_at
  output_ref? / error_code? / retryability?
```

模型网络请求和编译进程不能断点续跑。进程异常后，仍为 `started` 且租约过期的 Attempt 标记为 `abandoned`；符合策略时创建新 Attempt，绝不复用旧请求身份假装续传。

## 6. 核心状态转换

```text
Brief Revision
  -> StoryBlueprint Proposal
  -> accepted StoryBlueprint Revision
  -> WorkCanon Revision
  -> Outline / SceneContract Revisions
  -> SceneScript Revisions
  -> review Gates passed
  -> immutable ScriptRelease
  -> production ProductionRun pinned to that release
  -> PerformanceDraft Revision
  -> immutable BuildBundle
  -> deterministic .aap
```

跨边界只有三个正式入口：

- Proposal 被采纳后创建 Revision。
- Release Gate 通过后创建 ScriptRelease。
- 制作适配器接收 ScriptRelease 清单后创建制作 Run。

## 7. 最小持久化表

首个可实现版本至少包含：

```text
works
chapters
scenes
artifacts
revisions
script_releases
proposals
gates
blockers
production_runs
work_items
work_item_dependencies
job_attempts
decisions
```

对话可以晚于这些表接入。没有上述身份、版本与任务模型时，不应先发布“自动写完整作品”的承诺。

## 8. 必须验证的不变量

1. 重命名或移动章节后，Release 中的 Scene 引用仍有效。
2. 旧 Proposal 不能覆盖更新后的正文。
3. 冻结后的 ScriptRelease 无法原地修改。
4. 制作 Run 在创作侧出现新 Release 后仍固定使用原版本。
5. 进程重启后 WorkItem 可恢复，未完成的模型请求只会创建新 Attempt。
6. 同一 BuildBundle 在相同编译器与素材清单下产生可复现 `.aap`。
7. 每条已确认 Canon 都能回到来源 Revision 或人工决定。
8. Agent 对话即使被删除，也不影响任何正式产物的可解释性。
