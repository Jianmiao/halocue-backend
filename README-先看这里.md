# HaloCue 1.0 后端协作交接包

> 归档说明：本文件记录最初交接包结构。当前目录已拆为独立 HaloCue 后端仓库；`01-完整程序/`、`references/` 和 `MANIFEST-SHA256.txt` 只作为本地外部输入保留，不进入 Git，也不随仓库分发。当前仓库说明以根目录 `README.md` 为准。

这是一份面向后端协作者的最小、可运行交接包。它不是完整产品源码，也不包含尚未完成的 HaloCue 1.0 UI。

## 开始方式

1. 先阅读根目录的 `HaloCue-1.0-后端协作AI提示词.md`，把全文交给协作者使用的 AI。
2. 第一阶段只做提示词定义的 **B0：现状审计、测试基线、契约矩阵、契约测试**。不要立即重写后端或替换产品模型。
3. 将本目录作为工作区根目录。Python 建议使用 3.11 或 3.12。
4. 分别在 `08-HaloCue-1.0`、`09-HaloCue-1.0-Writing`、`10-HaloCue-1.0-Integrated` 中运行：

   ```powershell
   python -m pytest -q
   ```

5. 开始修改前，先记录三组测试基线和发现的问题；接口、所有权或领域名词有冲突时，以根目录提示词、`07-正式版产品设计` 和 `UBIQUITOUS_LANGUAGE.md` 为准，并明确报告歧义。

## 目录说明

- `07-正式版产品设计/`：正式领域模型和制作能力适配器契约。
- `01-完整程序/aa/`：制作后端运行与测试所需的 0.9.3 兼容层纯 Python 模块，以及资源索引和表情语义数据库。索引中的本机来源路径已清理；不含实际素材文件或个人配置。
- `08-HaloCue-1.0/`：AA 制作后端。负责剧本发布后的结构检查、选角映射、演出草稿、审查、编译和安装。
- `09-HaloCue-1.0-Writing/`：写作域。负责作品、章节、场景、正文修订和不可变 `ScriptRelease`。
- `10-HaloCue-1.0-Integrated/`：组合入口。保持写作域和制作域的边界，不复制两边实现。
- `references/StoryForge/`：新规划中制作/渲染引擎的最小架构与数据模型参考，不是当前产品 UI，也不能反向接管产品领域。
- `references/AA-0.8.8/`：AA 0.8.8 的最小只读数据结构参考，用于兼容性理解，不等于允许修改或分发完整反编译工程。
- `MANIFEST-SHA256.txt`：交接包内文件的相对路径、大小和 SHA-256，便于确认文件没有缺失或被改动。

## 必须保持的边界

- HaloCue 1.0 是大众用户看到的产品外壳；交互要清晰、低门槛。
- AA 的节点、对白、预览工作流可作为制作体验参考，但不直接暴露专业底层概念给普通用户。
- StoryForge 是可替换的制作/渲染引擎方向，不是新的产品领域，也不是当前 UI 的替代品。
- `aa_pipeline` 是内部素材、ASR、TTS、标注工具链，不属于普通用户运行时，本包没有携带。
- 写作域只通过不可变 `ScriptRelease` 向制作域交付；制作域不得直接编辑写作域的正文状态。

## 本包刻意不包含

用户作品与 `data/`、设置和 API 密钥、UI 设计工程及构建产物、缓存、发布包、完整 AA 反编译内容、游戏原始资源和素材文件、完整 StoryForge 工程、完整 `aa_pipeline`。为保证服务和测试可运行，本包只保留当前后端直接读取的少量静态页面文件、资源索引和语义元数据。

需要上述内容时，应先说明具体用途、最小所需文件和许可边界，再单独索取。不要把缺少这些大文件误判为交接包不完整。
